## 01 / Information baseline

# Controls before production.

Add dependable 3ds Max capacity without losing scene organization, source traceability, review ownership or downstream handoff control.

### Required inputs

- Approved drawings, models or reference information
- Required 3ds Max version and project setup
- Scene, object, layer, material and texture conventions
- Intended visualization, animation or downstream handoff use

### Naming and controls

- System units, display units, origin, orientation and scale
- Scene, object, layer, group, material and texture naming
- Source revision, asset owner, dependency and approval status
- Relative asset paths, archive structure and version register

### Standards and constraints

- The required 3ds Max version and native-scene compatibility are confirmed before production
- Renderer, plugin and script dependencies remain project-specific and are not claimed by default
- Licensed assets, textures, typefaces and media require documented rights before use
- Design-bearing changes proceed only from client-approved information and instructions

### Verified software and formats

- Autodesk 3ds Max scene production and `.max` source packages
- Project-agreed source and exchange formats confirmed before mobilization
- Self-contained archives using the agreed asset-path structure
- A version, dependency and known-limitations register accompanies handoff

## 03 / Delivery definition

# Acceptance is part of handoff.

### Deliverables

- Structured 3ds Max scene packages
- Purpose-built models and visualization-ready assets
- Material, lighting and scene-assembly setup
- Animation-support scenes or assets where agreed

### Acceptance criteria

- Scene opens in the agreed 3ds Max version with declared dependencies visible
- Units, origin, naming, hierarchy and asset paths follow the approved setup
- Source revision, assumptions, third-party assets and limitations are traceable
- Client approver accepts the package for its named visualization or animation use

### Structured handoff

- Versioned `.max` scene and agreed supporting assets
- Archive and asset-path structure
- Dependency, source and rights register
- Known limitations, open items and review record

### Evidence required

- Written scope approval
- Current source-information register
- Named client approvers
- Approved publication evidence

## Responsibility boundary

3ds Max production support follows client-approved inputs and intended uses. Axys3D does not act as architect or engineer of record and does not provide design certification, code approval or statutory sign-off.

## Technical FAQ

# Scope questions, answered precisely.

### Can Axys3D join an established 3ds Max production setup?

Yes, after the client confirms the required 3ds Max version, scene conventions, asset paths, declared dependencies and review ownership.

### Which renderers, plugins or scripts are supported?

No blanket renderer, plugin or script claim is made. The exact dependency set must be technically verified and founder-approved before it appears in public copy or a project scope.

### Can 3ds Max scenes support visualization and animation?

Yes, when geometry, hierarchy, materials, cameras, assets and output requirements are agreed for the specific downstream workflow.

### Does this service carry architectural or engineering responsibility?

No. Axys3D provides modeling, scene-production and delivery support. Design authority, code compliance and statutory or professional sign-off remain with appointed parties.
