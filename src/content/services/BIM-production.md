## 01 / Information baseline

# Controls before production.

Scale multidisciplinary model production while retaining agreed naming, exchange, federation and information-management controls.

### Required inputs

- Client BIM execution plan or production protocol
- Employer/client information requirements
- Discipline models and approved design information
- Common data environment conventions

### Naming and controls

- Client-issued container, file, view and sheet naming rules
- Model breakdown, origin, coordinate and federation conventions
- Revision, suitability/status and transmittal controls
- Named task owners, checkers and client approvers

### Standards and constraints

- Client BIM execution plan and information requirements govern production
- LOD/LOI definitions are confirmed per package; no universal stage equivalence is assumed
- Authoring version, exchange cadence and model-size limits are agreed before mobilization
- Only client-approved instructions alter design-bearing information

### Verified software and formats

- Revit-native model packages where Revit is the agreed authoring platform
- IFC exchanges where required by the client protocol
- NWC/NWD federation packages where included in the approved workflow
- BCF or project-agreed issue registers for traceable review items

## 02 / Scope and gates

# Production stays reviewable.

Axys3D progresses work against named inputs. Design-bearing decisions and approvals remain client-led.

### Technical scope

- Model-production planning and task breakdown
- Authoring against agreed container and naming rules
- Model health, coordination-readiness and issue checks
- Status tracking against package information requirements

### 01 — Audit issued requirements and model state

**Review gate:** Mobilization gate: requirements, responsibilities and source status accepted.

### 02 — Confirm responsibility matrix, milestones and exchange rules

**Review gate:** Sample gate: naming, model breakdown and representative output approved.

### 03 — Produce and check model packages

**Review gate:** Package gate: checker comments closed or explicitly carried.

### 04 — Submit through client-led review gates

**Review gate:** Issue gate: client authorizes status, exchange and transmittal.

### 05 — Close approved comments and package handoff

**Review gate:** Handoff gate: open items and archive contents acknowledged.

## 03 / Delivery definition

# Acceptance is part of handoff.

### Deliverables

- BIM production plan
- Discipline model packages
- Model audit and issue logs
- Federation-ready exchanges

### Acceptance criteria

- Package matches the agreed model breakdown, naming and exchange version
- Required model-health checks are recorded with exceptions visible
- Status, revision, assumptions and open issues are traceable
- Client-named approver accepts the package for its stated use

### Structured handoff

- Native and exchange files as agreed
- Model status and assumptions register
- Open-issue schedule
- Revision and transmittal record

### Evidence required

- Written scope approval
- Current source-information register
- Named client approvers
- Approved publication evidence

## Responsibility boundary

Production support only. Axys3D is not presented as architect, engineer of record, information manager of record or statutory approver.

Axys3D provides production, modeling, coordination or delivery support as scoped. It does not act as architect or engineer of record and does not provide statutory sign-off.

## Technical FAQ

# Scope questions, answered precisely.

### Can you work inside our BIM execution plan?

Yes. Production is configured to client-issued standards, model breakdown, exchange rules and approval routes.

### Do you set project LOD/LOI?

We help translate agreed requirements into production tasks; the client and appointed professionals approve the governing information requirements.

### Do you take design responsibility?

No. Axys3D provides model-production and delivery support; design authority and professional sign-off remain with the appointed parties.

### What establishes acceptance for a BIM package?

The agreed model breakdown, naming, exchange version, checks, open-item record and acceptance by the client-named approver for a stated use.
