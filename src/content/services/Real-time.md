## 01 / Information baseline

# Controls before production.

Translate approved project information into performant, reusable interactive environments with a clear deployment context.

### Required inputs

- Approved source models and data
- Target device and performance budget
- Interaction and navigation specification
- Distribution, security and rights requirements

### Naming and controls

- Source asset, level, map, object, material and interaction naming
- Engine version, plugin, build, target device and approval status
- Source-model revision and retained-data mapping
- Asset origin, license, ownership and redistribution status

### Standards and constraints

- Target hardware, interaction scope and measurable performance budget are agreed before optimization
- Engine version and plugin dependencies are frozen for the approved package
- The real-time derivative is not the authoritative BIM or design record
- Streaming, public hosting, portal access and distribution infrastructure remain deferred

### Verified software and formats

- Unreal Engine project and packaged local review build
- Project-approved source geometry and texture formats
- Selected BIM/object data only where a mapping and performance need are agreed
- Versioned asset, plugin, build and performance registers

## 02 / Scope and gates

# Production stays reviewable.

Axys3D progresses work against named inputs. Design-bearing decisions and approvals remain client-led.

### Technical scope

- Unreal Engine scene production
- Geometry, texture and lighting optimization
- Interaction and UI prototyping
- Packaged review-build support

### 01 — Define device, performance and interaction targets

**Review gate:** Definition gate: device, interaction, data and performance targets accepted.

### 02 — Prepare and optimize approved assets

**Review gate:** Prototype gate: representative space, controls and visual quality approved.

### 03 — Build representative technical prototype

**Review gate:** Content gate: optimized assets and retained information reviewed.

### 04 — Integrate interactions and test accessibility/usability

**Review gate:** Usability gate: navigation, keyboard path and known limitations accepted.

### 05 — Package approved development build and sources

**Review gate:** Handoff gate: build, source, dependencies, rights and test record acknowledged.

## 03 / Delivery definition

# Acceptance is part of handoff.

### Deliverables

- Optimized Unreal Engine scene
- Material and lighting systems
- Interactive review build
- Technical source handoff

### Acceptance criteria

- Build launches on the named test configuration and exposes agreed interactions
- Performance is reported against the agreed device and test scene, without generalized claims
- Source revision, retained data, assets, plugins and limitations are traceable
- Client accepts the local build and source package for its stated review purpose

### Structured handoff

- Versioned project and packaged build
- Performance profile
- Asset and plugin register
- Known limitations and test record

### Evidence required

- Written scope approval
- Current source-information register
- Named client approvers
- Approved publication evidence

## Responsibility boundary

Real-time outputs are communication and review tools, not statutory models or professional approval instruments.

Axys3D provides production, modeling, coordination or delivery support as scoped. It does not act as architect or engineer of record and does not provide statutory sign-off.

## Technical FAQ

# Scope questions, answered precisely.

### Can BIM data be retained?

Selected structured data can be mapped into the experience when use cases and performance limits are defined.

### Is hosting included?

No. Streaming, cloud deployment and portal infrastructure are explicitly deferred.

### Does the build replace the authoritative model?

No. It is a communication or review derivative; the client-governed source remains authoritative.

### How are performance claims controlled?

Results are reported only against the agreed device, build version, test scene and quality settings; no generalized frame-rate or hardware claim is made.
